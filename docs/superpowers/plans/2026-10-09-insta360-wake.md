# Insta360 finite wake software route Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement source-backed finite wake advertising and per-peer preparation without inventing recording observations or replacing the shared BLE host.

**Architecture:** A pure encoder supplies fixed AD buffers. A four-slot owner scheduler uses one retained advertising worker and an explicitly qualified recovery provider. An opt-in RecordingPreparation bridge preserves the existing group's sole REC authority; missing Insta360 adapters finish Unsupported and keep the full issue open.

**Tech Stack:** C++11, Unity 2.6.1, PlatformIO Core 6.1.18, pinned ESP32/Arduino packages and NimBLE-Arduino 2.3.6 at dfb4ac561a06797081be9e752902a6582e7f029e; Python unittest SDK harnesses.

**Spec:** [Approved design](../specs/2026-10-09-insta360-wake-design.md).

## Global Constraints

- Commit verified changes directly to main; no new issue, firmware upload, NVS commissioning, model confirmation or hardware trial.
- Four fixed peer slots, matching the shared transport capacity, and at most one active advertising lease.
- Configurable total request timeout defaults to 15000 ms and advertising slice to 3000 ms. Both must be nonzero and less than 2^31 ms; the slice cannot exceed the total timeout.
- Queue time counts against the original total request deadline. No retry resets that deadline.
- One advertising attempt per request, with no automatic repeat after uncertain SDK delivery.
- Default profile is Disabled. Exactly six printable ASCII identifier bytes; never derive from a MAC, pad, truncate or infer from a model enum.
- Public status contains counts and errors only; identifiers remain in fixed RAM.
- Construction has no SDK calls; activation is opt-in and requires an already Ready, source/store-qualified Esp32BleHost.
- Existing camera commands keep their existing service route. No extra CameraManager/RecordingManager tick.
- SDK calls can stall indefinitely: software intent deadlines remain bounded, while release may remain quarantined.
- Keep #9's complete acceptance criteria intact. Missing actual Insta360 adapters and recording observations remain open dependencies.

## Review Focus

1. Cancellation after preparation but before SDK admission: no later start/recovery is admitted; an already admitted call is not falsely reported retracted (Tasks 2/3/4).
2. Stale identity, duplicate request or reused operation across reset: no old publication or observation advances replacement intent (Tasks 2/5).
3. Full host queue or missing disconnect/barrier: terminal intent does not free callback storage or allow another advertisement (Tasks 3/4).
4. Pairing/store activity from a wake-only incoming connection: refuse its security mutations without deleting a bond or terminating an established peer (Task 4).
5. Contention with scan/connect/bond reset while other peers have deadlines: finite Busy deferral and honest partial results, without stopping foreign GAP activity (Tasks 2/3/4).

## API names shared by all tasks

Declare these types once, in their owning headers. No task invents a parallel operation token.

```cpp
namespace ridesync {
namespace insta360 {
enum class WakeProfile : uint8_t { Disabled, M5WakeV1 };
enum class WakeCodecError : uint8_t {
  None, Disabled, UnsupportedProfile, InvalidIdentifier, UnsupportedName
};
struct WakeIdentifierResult {
  WakeCodecError error = WakeCodecError::Disabled;
  std::array<uint8_t, 6> bytes{};
};
struct WakeEncoding {
  WakeCodecError error = WakeCodecError::Disabled;
  std::array<uint8_t, 31> advertisement{};
  std::array<uint8_t, 25> scan_response{};
};
WakeIdentifierResult deriveWakeIdentifier(WakeProfile, const char *, size_t);
WakeEncoding encodeWake(WakeProfile, const uint8_t *, size_t);
}
struct WakeOperation {
  uint8_t peer = 0;
  uint32_t generation = 0, id = 0;
};
enum class WakeSubmit : uint8_t { Accepted, Busy, Unsupported, Failed };
enum class WakePhase : uint8_t {
  Queued, Advertising, Releasing, Recovering, Ready,
  Unsupported, Failed, Cancelled, Timeout
};
struct WakeRadioResult {
  WakeOperation operation;
  bool submitted = false, terminal = false, released = false;
  int sdk_error = 0;
};
class WakeRadio {
public:
  virtual ~WakeRadio() = default;
  virtual WakeSubmit begin(const WakeOperation &, const insta360::WakeEncoding &,
                           uint32_t deadline, uint32_t now) = 0;
  virtual void cancel(const WakeOperation &) = 0;
  virtual WakeRadioResult poll(const WakeOperation &, uint32_t now) = 0;
};
struct WakeRecoveryResult {
  WakeOperation operation;
  bool terminal = false, released = false, fresh = false;
  RecordingState observed = RecordingState::Unknown;
  CameraError error = CameraError::None;
};
class WakeRecovery {
public:
  virtual ~WakeRecovery() = default;
  virtual CameraError begin(const WakeOperation &, uint32_t deadline) = 0;
  virtual WakeRecoveryResult poll(const WakeOperation &, uint32_t now) = 0;
  virtual void cancel(const WakeOperation &) = 0;
};
struct WakePolicy { uint32_t total_ms = 15000, slice_ms = 3000; };
struct WakePeerConfig {
  bool enabled = false, source_qualified = false;
  insta360::WakeProfile profile = insta360::WakeProfile::Disabled;
  std::array<uint8_t, 6> identifier{};
};
struct WakeStatus {
  WakeOperation operation;
  WakePhase phase = WakePhase::Unsupported;
  CameraError error = CameraError::Unsupported;
  bool released = true;
  RecordingState observed = RecordingState::Unknown;
};
class WakeManager {
public:
  WakeManager(WakeRadio &, WakeRecovery * = nullptr);
  CameraError request(const WakeOperation &, const WakePeerConfig &,
                      const WakePolicy &, uint32_t now);
  void cancel(uint8_t peer);
  void invalidate(uint32_t new_generation);
  void service(uint32_t now);
  WakeStatus status(uint8_t peer) const;
};
}
```

Operation equality compares peer, generation and id. Valid IDs/generations are
nonzero and less than UINT32_MAX. Manager records the largest admitted id per
peer across invalidate(), rejects non-increasing ids, and records one current
configuration generation. Changing generation seals all previous requests; a
request cannot silently replace unreleased storage. Driver only reports matching
results; the manager independently verifies the publication's operation.
Recovery released means its pending recovery/query procedure storage is no
longer borrowed; it does not require closing the successfully established
control connection. Radio released, in contrast, includes retirement of every
connection accepted by the wake-only advertising lease.

```cpp

uint32_t now = uint32_t(millis());
if (!leaseCurrentAndOpen(now)) return;
```

free callback storage. Successful stop with no SDK completion callback uses the
pinned host barrier as a separate release condition, as existing scan retirement
does. Failed cleanup never manufactures terminal/quiescent state.

its typed identity with the same pinned connection-descriptor query used by the
existing host callback, and publish its refusal ownership before callback return.

operations; guardedRead/guardedWrite/guardedDelete consult the tracked typed

operations without calling the persistent store. Preserve foreign identity
operations and never erase data. If identity resolution, alias classification or
handle ownership is ambiguous, fail closed and quarantine; refuse ambiguous
peer-specific store access during that lease. Do not replace store callbacks,
turn off global bonding, or change security on established peers. Test all
pinned store record schemas that can name the incoming peer, including resolved
and RPA records, rather than only OUR_SEC.

Counters, callback references and barrier queue publication are retained until
actual terminal/disconnect and quiescence. Queue a barrier with zero wait using
the pinned event representation already used by Esp32BleHost. Full queue keeps
release false and seals the lease; callbacks cannot revive it. Callback body
publishes metadata only and never calls a group/camera owner or submits cleanup.
Publication uses atomics or a nonblocking copy gate; a failed copy cannot lose
a connection reference and claim release. Latch a conservative fault/quarantine
with atomic owned-handle/ref counters on publication contention. service/poll
never waits for the worker or host callback gate. Payload and operation storage
are immutable until release; reject reuse rather than overwrite borrowed data.
