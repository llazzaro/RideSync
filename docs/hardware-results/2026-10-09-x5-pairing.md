# X5 CE80 remote pairing — October 9, 2026

The owner placed the X5 in remote-search mode and removed the board's microSD
card. The actual board is the photographed LILYGO T-A7670E V1.4 with
ESP32-WROVER-E and A7670E-FASE. This trial used the isolated
[`x5_peripheral` diagnostic](../../tools/bench/x5_peripheral/README.md) built
from `d71db1f81d511216c7c8b140049a592cd2c61571`, not the production application.
The X5 firmware version remains unrecorded.

Compared with the preceding corrected probe trial, the only firmware change
was its GAP/scan-response name: `Insta360 GPS Remote` replaced
`RideSync CE80 Probe`, matching both pinned MIT community examples. The CE80
and additional D0FF service, GATT fields, nonbonding RAM store, NVS refusal
guards and finite capture policy were unchanged. Four uploaded flash regions
were hash-verified. The private upload provenance retains the firmware hash.

## Observed result

One explicit A attempt opened a 120-second window, with H enabling private
incoming-byte capture. A separate eight-second passive Mac scan observed the
expected name and CE80/D0FF service UUIDs. The probe then recorded:

| Event | Boot time / observation |
|---|---|
| Successful connection | 41.618 s; connection handle 0, public address type |
| ATT MTU | Initially 23; changed to 251 at 44.543 s |
| CE82 subscription | 45.854 s; notifications enabled on value handle 18 |
| First CE81 write | 46.245 s; value handle 16, seven bytes |
| Incoming traffic | 96 CE81 writes in total; no characteristic reads or security events |
| Camera display | Owner twice confirmed the remote connected/paired |
| Window expiry | 121.844 s boot time; stop reason 3 |
| Cleanup | Subscription disabled, then disconnect at 121.907 s; terminate SDK return 0 |

All 117 events were reported, with zero drops, zero ingress truncation and no
queued events at the end. Final state was inactive, advertising off, no peer,
no SDK operation in flight and NVS refusal counters init/open/erase `1/2/0`.
The disconnect followed the diagnostic's intended finite deadline; it was not
an unexplained camera disconnect. No shutter notification was sent.

This establishes a usable CE80 pairing/subscription path on this bench and
camera, including the owner's UI confirmation. The contrast supports the name
alignment for this setup; one successful trial does not establish a universal
name-filter rule or compatibility across firmware. Incoming bytes remain
unclassified and private: neither their length nor periodic arrival proves
recording state. Issues #3 and #19 remain open for actual control work.

## Reproduction and preservation

Use the pinned diagnostic build and its ELF guard audit, keep the X5 searching
for a remote, and issue A once after idle boot. H is optional and makes the raw
transcript sensitive. The diagnostic disconnects when its window ends; another
attempt requires a fresh boot. Opening serial with DTR and RTS deasserted
avoids an incidental ESP32 reset. No SD card is required for this BLE test.
Refer to the diagnostic README for exact commands and limitations.

The pre-trial 20 KiB NVS readback at `0x9000` matched the preserved factory
baseline. Post-trial readback matched those pre-trial bytes exactly. That
readback reset the ESP32 into idle diagnostic startup. Raw transcripts,
peripheral identifiers and binary backups stay outside Git.

## Separate one-shot shutter trial

The reviewed diagnostic at `55c33db1bce626ae0eaa3539de8105f1786bc581` adds an
explicit S command using the shared source-derived shutter encoder. Its focused
host harness, pinned SDK build and final-ELF guard audit passed; exact-head CI
`37854324117` also passed. Four uploaded regions were hash-verified. The board's
SD slot remained empty. This does not establish whether the camera has a card.

After a fresh A, the X5 connected at boot time 18.478 s, negotiated ATT MTU 251
and enabled CE82 notifications at 21.530 s. The owner confirmed the camera
display showed connected, then explicitly requested recording. One S was
accepted at 40.033 s; one addressed CE82 notification submission returned SDK
status 0 at 40.035 s. No automatic or second shutter event was sent.

When asked whether the recording indicator/timer appeared, the owner answered
yes but also reported that the X5 had no SD card and could not record. This is
not evidence of a completed video recording or saved media. Recording status
remains unclassified; SDK status 0 proves neither camera delivery nor recording.
The next REC/STOP test needs a card installed in the **camera**, independently
of the board's card slot.

The probe recorded disconnect reason 531 at 69.695 s, before the host's later
explicit X request. Final stop reason was Disconnected (4), with advertising
off, no peer, no SDK work in flight and no pending shutter request. All 78
events were reported without drops/truncation, including 56 CE81 writes and
exactly one shutter request/result. Post-trial NVS readback matched the
pre-trial factory baseline byte for byte. Issues #3/#19 remain open.

## Card-ready recording retry — firmware 1.11.10

The owner reported a camera microSD card installed and firmware 1.11.10. The
existing diagnostic was used without a firmware upload. An initial command
during serial startup did not start an attempt; keeping serial open and issuing
one A after startup opened the finite capture window. Private hex stayed off.

The X5 connected at boot 50.795 s and enabled CE82 notifications at 51.672 s.
After the owner confirmed video mode and stopped recording, one S was accepted
at 87.134 s; the single SDK submission returned 0 at 87.137 s. The owner
confirmed a running recording timer. The diagnostic expired at 123.756 s and
disconnected at 123.841 s. The owner then stopped recording with the camera
button and confirmed the new clip plays in camera playback.

This establishes one camera-observed remote recording start and a playable
clip on this setup. It does not establish remote Stop: this clip was stopped
manually after the finite window expired. All 106 events were reported with
zero drops/truncations, including one shutter request/result and 83 CE81
writes. Final state had no peer, no pending shutter, no SDK work in flight;
NVS refusal counters were 1/2/0. No new NVS readback was performed. The
incoming writes remain unclassified, so recording state is still UNKNOWN in
software. #3 remains open for three remote REC/STOP cycles and reconnect
evidence; #19 remains open for authoritative receive/state decoding.
